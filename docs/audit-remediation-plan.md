# План исправлений Lixun

Основание — полный прогон коммита `b82af3c` от 20 ноября 2026 года. В двух запусках workspace прошёл 1061 тест, в каждом были пропущены восемь. Семь из них прошли отдельно. Тест измерения PDF-виджета аварийно завершился. Сборка release, восемь вариантов сборки и проверка текстового и PDF-просмотра в запущенном GUI прошли. Проверки двоичного IPC на непустой выдаче, форматирования, строгого Clippy и скрипта семантического QA выявили отдельные дефекты.

## A. Приватность и безопасный запуск тестов

1. **A1. Убрать содержимое ввода из журналов.** Сейчас GUI пишет запрос, нажатия клавиш и скопированный текст, а командный источник может записать отклонённую команду. Оставить код события, длительность, число результатов и класс ошибки. Проверить также отладочные логи IPC, действий и демона, включая идентификаторы, в которые источник помещает исходный текст. **Приёмка.** Временный профиль вводит, ищет, копирует и отклоняет разные синтетические маркеры. В журнале обычного и отладочного запуска отсутствуют маркеры и последовательность введённых клавиш. [Ввод](../crates/lixun-gui/src/window.rs) · [Клавиши](../crates/lixun-gui/src/keymap.rs) · [Буфер](../crates/lixun-gui/src/actions.rs) · [Командный источник](../crates/lixun-source-shell/src/source.rs)
2. **A2. Применять одно решение о сохранении ко всем следам запроса.** Сейчас история запросов учитывает исключение источника, а связь «запрос → документ» и частота открытий записываются отдельными путями. Принять решение до изменения любого хранилища. Расширить контракт источника для запроса и результата, учесть отдельный `RecordClick` старого клиента и идентификаторы, содержащие команду. Для ранее записанных данных предложить локальный предварительный просмотр и явную очистку собственных хранилищ Lixun. **Приёмка.** После открытия результата, завершения демона и повторного запуска маркер отсутствует в истории, недавних результатах и файлах персонализации. Разрешённые запросы по-прежнему обучают ранжирование. [Запись кликов](../crates/lixun-daemon/src/main.rs) · [Контракт источника](../crates/lixun-sources/src/source.rs)
3. **A3. Сохранить границы индексации при ошибке конфигурации.** Различать первый запуск без файла, ошибку чтения, повреждённый TOML и некорректное регулярное исключение. При ошибке сохранять управление через CLI и показывать причину. Новое сканирование, наблюдение за каталогами, OCR и задания источников запускать только с проверенной областью. Если её нельзя восстановить, приостановить эти операции. **Приёмка.** После изменения рабочего конфига на ошибочный и после холодного запуска ни один путь за пределами разрешённого набора не читается для индексации. После исправления конфига работа возобновляется. [Загрузка конфигурации](../crates/lixun-config/src/lib.rs) · [Запуск демона](../crates/lixun-daemon/src/main.rs)
4. **A4. Ограничить рестарт-тест его собственным процессом.** Интеграционный тест завершает процессы по совпадению имени. Сохранить дескриптор или PID дочернего процесса тестового супервизора, изолировать runtime и каталоги данных. **Приёмка.** Два экземпляра тестовой среды работают одновременно. Завершение одного воркера приводит к его восстановлению, второй продолжает отвечать с тем же PID. [Тест супервизора](../crates/lixun-daemon/tests/semantic_supervisor.rs)

## B. Индекс и фоновые процессы

1. **B1. Единые правила допуска путей.** Полный обход, наблюдатель и ручной запрос для файла или каталога должны использовать одинаковые корни, строковые и регулярные исключения, внутренние каталоги и исключения источников. Определить поведение символических ссылок и применять его до извлечения содержимого и постановки в OCR. На этой же функции основать существующую команду `check-exclude`. **Приёмка.** Для матрицы «разрешённый файл, исключённый файл, исключённый родитель, ссылка, каталог данных, каталог источника» все точки входа дают одинаковое решение и объяснимую причину. [Ручная индексация](../crates/lixun-indexer/src/indexer.rs) · [Сборка источника](../crates/lixun-daemon/src/sources_glue.rs) · [CLI](../crates/lixun-cli/src/main.rs)
2. **B2. Устранить остановку наблюдателя при большом импорте.** Сейчас обработчики каталога могут оба ожидать свободного места в той ограниченной очереди, которую сами же опустошают. Отделить перечисление дочерних файлов от потребителей очереди. При переполнении назначать сверку поддерева с учётом удалений. **Приёмка.** Импорт нескольких каталогов крупнее вместимости очереди завершается при ограниченной памяти. Создание, перемещение и удаление во время импорта отражаются в поиске, следующее событие обрабатывается. [Наблюдатель](../crates/lixun-indexer/src/watcher.rs)
3. **B3. Сверять полный индекс с диском.** Полный обход начинает с пустого манифеста и обновляет найденные документы. Удалённый файл может остаться в поиске. Сверять документы файлового источника по успешно пройденным корням, применять удаления к поисковому индексу и публиковать манифест после подтверждённой записи. Учесть прерывание, недоступный том и параллельные события наблюдателя. **Приёмка.** Удалённый файл исчезает из реальной выдачи после полной перестройки и перезапуска. При временно недоступном томе его документы сохраняются, доступные корни обновляются, объекты других источников сохраняются. [Перестройка](../crates/lixun-indexer/src/indexer.rs) · [Текущий тест манифеста](../crates/lixun-daemon/tests/reindex_full.rs)
4. **B4. Передавать источникам причину перестройки.** Различать явный запрос, обычный старт и смену схемы. Сейчас явный полный запрос может пропустить вложения, поскольку использует флаг автоматического восстановления. **Приёмка.** Ручная перестройка восстанавливает тестовое вложение, автоматическая сохраняет политику источника. Решение об участии принимает сам источник. [Политика перестройки](../crates/lixun-indexer/src/indexer.rs) · [Источник вложений](../crates/lixun-source-thunderbird/src/attachments.rs)
5. **B5. Ограничить время работы внешней команды вместе с чтением её вывода.** Сейчас потомок может удерживать канал открытым после завершения родителя. Ограничить общим дедлайном ожидание процесса и чтение унаследованных каналов, завершать свою группу процессов при отмене и собирать дочерний процесс. **Приёмка.** При отмене, таймауте и обычном выходе родителя команда с дочерним процессом, удерживающим канал, возвращает управление в установленный срок. [Запуск команды](../crates/lixun-source-command/src/runner.rs)

## C. Протокол и команды пользователя

1. **C1. Исправить двоичный IPC.** В прогоне v4/JSON передал файл и приложение, v5/Postcard сломался на обоих. Условно пропускаемые поля и нетегированные варианты человекочитаемого формата несовместимы с текущим двоичным представлением. Кроме того, `FrameCodec` использует JSON независимо от записанной версии. Выделить стабильные структуры протокола с явными вариантами и направить обе реализации кадрирования через один выбор кодека. Сохранить v4 по умолчанию до проверки совместимости. Если меняется опубликованное представление v5, выделить новую версию и явно согласовывать поддерживаемую. **Приёмка.** Старый и новый клиент общаются с поддерживаемыми версиями демона. На настоящем сокете проходят непустая выдача файла, приложения и плагина, пустые поля и действия. Неподдерживаемая версия получает явную ошибку. [Представление результата](../crates/lixun-core/src/lib.rs) · [Кодеки](../crates/lixun-ipc/src/lib.rs)
2. **C2. Разделить размер индекса и объём обработанной работы.** После перезапуска поиск и семантическая обработка видели четыре документа, а статус показывал ноль. Считать доступные документы по зафиксированному индексу, отдельно показывать прогресс операции. Использовать дешёвый счётчик снимка или обновление после записи. **Приёмка.** Оба варианта статуса показывают четыре после перезапуска, четыре после повторной перестройки и три после удаления с фиксацией. [Статистика демона](../crates/lixun-daemon/src/main.rs)
3. **C3. Возвращать достоверный результат команд GUI.** При медленном первом запуске `show` получил ошибку и завершился с кодом 0. Передавать ошибку демона в код завершения CLI. Координировать одновременные запросы запуска, подтверждать готовность через установленное соединение, различать ожидание и отказ. **Приёмка.** Успех даёт код 0, отказ или истечение времени — ненулевой. Два одновременных вызова поднимают один GUI, повторная доставка одного `toggle` не скрывает только что показанное окно. [Ответ CLI](../crates/lixun-cli/src/main.rs) · [Управление GUI](../crates/lixun-daemon/src/gui_control.rs)

## D. Зависимости и воспроизводимость проверок

1. **D1. Разобрать весь отчёт по зависимостям.** На проверенном lock-файле аудит зарегистрировал 34 совпадения в 16 пакетах. Отдельные категории предупреждений содержали 12 записей о неподдерживаемых пакетах, 28 о нарушениях гарантий безопасности кода и 3 об отозванных версиях. Для каждой записи установить цепочку, активные функции, платформу, доступность проблемного API и решение. Сначала проверить SQLite, которым источник читает внешнюю почтовую базу, и обновить прямую и транзитивные ветви `lru`. Зафиксированные минимумы для соответствующих предупреждений — `libsqlite3-sys 0.39.0` и `lru 0.18.2`. Непосредственно перед обновлением сверить исправленные совместимые версии. Отдельно проверить архивы, сетевые зависимости, инструменты сборки и зависимости векторного поиска. **Приёмка.** По каждой записи есть исправление либо обоснование с областью действия и сроком пересмотра. На обновлённых зависимостях проходят чтение почтовой базы, PDF-кеш, извлечение документов и поиск по существующему векторному индексу. 2. **D2. Вернуть CI способность обнаруживать эти дефекты.** Исправить удалённые feature-флаги в семантическом QA, установить необходимые системные зависимости в чистом runner и запускать тесты workspace. В матрице IPC исполнять клиентские сценарии для обоих форматов. Инициализировать GTK в правильном потоке теста PDF и запускать GUI-набор под headless-композитором. Устранить шесть сообщений `double_must_use` в интерфейсах с асинхронным макросом, отдельным изменением отформатировать 43 затронутых файла, поправить ссылки и предупреждения Rustdoc. **Приёмка.** С чистого checkout зелёные workspace-тесты, форматирование, строгий Clippy, документация, feature-матрица и release QA. Отдельная задача действительно исполняет OCR, PDF, рестарт воркера, отмену и smoke-тест интерфейса. ## E. Выдача, качество поиска и границы плагинов

1. **E1. Уважать скрытие и фильтр для окончательной страницы.** Источник, целиком перехвативший запрос, добавляет результаты после проверки скрытых документов. Ошибка сохранения скрытия или сброса персонализации может завершаться ответом об успехе. Лучший результат выбирается до фильтра категории и обрезки страницы. Фильтровать скрытые результаты при каждом способе выдачи, согласованно сохранять изменение и учитывать реальную видимую страницу при выборе лучшего результата. Сохранить семантику префиксов, зарезервированных источниками. **Приёмка.** Скрытый объект исчезает также из выдачи по префиксу и после перезапуска. При отказе записи клиент получает ошибку и может повторить операцию. Идентификатор лучшего результата либо отсутствует, либо присутствует в возвращённой странице. [Обработка выдачи и скрытия](../crates/lixun-daemon/src/main.rs)
2. **E2. Перенести решение об оформлении строки владельцу данных.** GUI определяет, каким категориям показывать относительную дату вместо подписи. Ввести общее описание подписи результата, которое заполняет источник. Общий виджет локализует и отображает значение. Согласовать передачу новых полей с C1. **Приёмка.** Почта и вложения сохраняют существующий вид, другой источник может запросить ту же подпись, тест общего виджета работает с произвольным источником. [Строка выдачи](../crates/lixun-gui/src/factory.rs)
3. **E3. Измерить и исправить ошибки смешанного ранжирования.** В малом синтетическом корпусе текстовый запрос поставил однотонное изображение выше релевантного текста. Этого достаточно для контрольного примера. Для изменения алгоритма собрать размеченные запросы на точные имена, короткие коды, синонимы, изображения и RU/EN/ZH. Разделить настройку и проверку. Сравнить лексический поиск, текущую комбинацию и варианты выбора каналов или весов. **Приёмка.** На отложенной выборке улучшилась nDCG@10 для проблемного класса. Recall@5 и первые места точных имён сохраняются в согласованном допуске, p95 первой выдачи укладывается в бюджет проекта. [Объединение результатов](../crates/lixun-fusion/src/handle.rs) · [Бюджет производительности](perf-budget.md)

Перед изменением функций проверять вызывающие места и риск через граф проекта. Для исправлений, меняющих форматы данных или миграции зависимостей, проверять обновление на копии профиля предыдущей версии. Продуктовые эксперименты и их условия запуска описаны [отдельно](search-feature-plan.md).

## Результаты исправлений, 20 ноября 2026 года

Сквозные проверки на Linux x86-64 используют синтетические профили. Они проверяют запуск с ошибочным TOML и восстановление, приватность и очистку истории, скрытие и отказ записи, ручную индексацию, импорт 2 060 файлов с переименованием и удалением. Через настоящий сокет проверяются поиск файла, приложения и вычисления в IPC v4, v5 и v6, отклонение неизвестной версии и отмена поиска. Клиент запрашивает возможности через отдельное соединение v4 перед выбором двоичного формата. Для смешанного парка по умолчанию используется v4. Произвольные значения JSON от плагинов поддерживают v4 и v6. У старого декодера Postcard собственное ограничение для непустой выдачи, которое снимает обновление клиента. [Сквозные проверки](../tests/daemon-regressions.py) · [Тесты сокета](../crates/lixun-daemon/tests/cancellation.rs) · [Release QA](../scripts/qa-wave-d.sh)

**Локальная проверка.** Прошли 1 068 тестов основного прогона. Все девять тестов с пометкой `ignored` исполнены отдельно, в том числе реальный Tesseract, PDF-виджеты под Xvfb и отмена через сокет. Прошли строгий Clippy, Rustdoc, форматирование, сборки матрицы, release QA и поиск в обе стороны между прежней и новой версиями CLI и демона. GUI на headless Wayland с Cairo прошёл два одновременных вызова показа окна, копирование пути, просмотр PDF и повторное открытие. В пробе с автоматическим выбором рендерера на виртуальном выходе процесс завершился с переполнением стека. Проверка на обычной графической сессии остаётся открытой. Следующий чистый запуск GitHub Actions проверит окружение runner. В конфигурации семантического воркера без `idle-eviction` компилятор сообщает о неиспользованном поле `clip_text`.

**Поиск.** Для настройки использовались 7 запросов, в отложенную выборку вошли 13. На шести отложенных текстовых запросах гибридная nDCG@10 выросла с 0,516 до 0,991, Recall@5 — с 0,944 до 1,000. Точность первого результата выросла с 0/6 до 6/6. Для изображений (2 запроса), точных имён (3) и многоязычной выдачи (2) все первые места сохранились. На копии индекса предыдущего релиза из четырёх документов запрос про врача первым вернул текст, запрос про оранжевый квадрат — единственное изображение. В трёх чередующихся прогонах медиана p95 первой страницы составила 1,12 мс до изменения и 1,37 мс после. Замер первой страницы и бюджет P99 полной выдачи измеряют разные интервалы.
